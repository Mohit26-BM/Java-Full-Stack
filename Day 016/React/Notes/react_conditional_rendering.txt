REACT 19 + TYPESCRIPT: CONDITIONAL RENDERING
Complete Examples from Beginner to Advanced
============================================

HOW TO USE THIS FILE
--------------------
These examples use React 19 with TypeScript and Vite. Each example is a
self-contained component. To try one, paste the code into a .tsx file inside
src/ and render that component from App.tsx.

Example App.tsx:
----------------
import Example1 from "./Example1";

function App() {
  return <Example1 />;
}

export default App;

You can name each component/file as you prefer. Examples that use useState
must be rendered inside a React application. Import useState from "react".



WHAT IS CONDITIONAL RENDERING?
------------------------------
Conditional rendering means displaying different JSX depending on a condition.
For example, show "Welcome" when a user is logged in and "Please log in" when
they are not.

Important:
- Use JavaScript expressions inside JSX braces: {condition && <p>...</p>}
- Use a ternary for a choice between two outcomes: condition ? A : B
- Use if/else or switch before the return when logic is more involved.
- Use useState when the condition must change in response to user interaction.
- Use a stable key when rendering arrays with map().
- Avoid {count && <p>...</p>} when count might be 0, because React may render 0.
  Prefer {count > 0 && <p>...</p>}.

EXAMPLE 1: IF/ELSE BEFORE RETURN
----------------------------------
Scenario: Show a login message.

function LoginMessage() {
  const isLoggedIn: boolean = true;

  if (isLoggedIn) {
    return <h2>Welcome back!</h2>;
  } else {
    return <h2>Please log in.</h2>;
  }
}

Explanation:
- isLoggedIn is true, so the first return is used.
- Change it to false to display "Please log in."
- A return ends the function, so only one branch is rendered.

EXAMPLE 4: LOGICAL OR (||) FOR A FALLBACK VALUE
------------------------------------------------------------
Scenario: Display a default name when no name is provided.

function Greeting() {
  const name: string = "";

  return <h2>Hello, {name || "Guest"}!</h2>;
}

Note: || returns the fallback when the left side is falsy. For numeric values
where 0 is valid, consider ?? instead.

------------------------------------------------------------
EXAMPLE 5: NULLISH COALESCING (??)
------------------------------------------------------------
Scenario: Use a default quantity only when the value is null or undefined.

function QuantityLabel() {
  const quantity: number | null = 0;

  return <p>Quantity: {quantity ?? 10}</p>;
}

Output: Quantity: 0

Unlike ||, ?? does not replace a valid 0 or an empty string.

EXAMPLE 8: SWITCH STATEMENT
------------------------------------------------------------
Scenario: Render a message based on order status.

function OrderStatus() {
  const status: string = "SHIPPED";
  let message: string;

  switch (status) {
    case "PENDING":
      message = "Your order is pending.";
      break;
    case "SHIPPED":
      message = "Your order has shipped.";
      break;
    case "DELIVERED":
      message = "Your order was delivered.";
      break;
    case "CANCELLED":
      message = "Your order was cancelled.";
      break;
    default:
      message = "Unknown order status.";
  }

  return <p>{message}</p>;
}

EXAMPLE 15: FILTER ITEMS BEFORE RENDERING
------------------------------------------------------------
interface Item {
  id: number;
  name: string;
  active: boolean;
}

function ActiveItems() {
  const items: Item[] = [
    { id: 1, name: "Item A", active: true },
    { id: 2, name: "Item B", active: false },
    { id: 3, name: "Item C", active: true }

  return (
    <div>
      <h2>Active Items</h2>
      {activeItems.length === 0 ? (
        <p>No active items.</p>
      ) : (
        activeItems.map((item) => <p key={item.id}>{item.name}</p>)
      )}
    </div>
  );
}

EXAMPLE 35: CONDITIONAL RENDERING FOR API STATES
------------------------------------------------------------
type ApiState =
  | { status: "loading" }
  | { status: "error"; message: string }
  | { status: "success"; products: string[] };

function ApiStateExample() {
  const state: ApiState = {
    status: "success",
    products: ["Laptop", "Mobile", "Tablet"]
  };

  if (state.status === "loading") {
    return <p>Loading products...</p>;
  }

  if (state.status === "error") {
    return <p role="alert">Error: {state.message}</p>;
  }

  return (
    <div>
      <h2>Products</h2>
      {state.products.length === 0
        ? <p>No products available.</p>
        : state.products.map((product) => <p key={product}>{product}</p>)}
    </div>
  );
}

This discriminated union lets TypeScript understand which fields exist in each
state. The state is hard-coded here for demonstration.

    if (status === "failed") return <span>Payment failed</span>;
    return <span>Unknown payment status</span>;
  }

  return <div>{renderStatus()}</div>;
}

A helper function can make the main JSX easier to read when the logic is reused
or becomes lengthy. Keep it simple and avoid unnecessary abstraction.

============================================================
COMMON MISTAKES AND BEST PRACTICES
============================================================

1. Mistake: Rendering 0 unintentionally
   Avoid: {quantity && <p>In stock</p>}
   Prefer: {quantity > 0 && <p>In stock</p>}

2. Mistake: Forgetting the alternative in a ternary
   Incorrect: {isLoggedIn ? <p>Welcome</p>}
   Correct:   {isLoggedIn ? <p>Welcome</p> : <p>Please log in</p>}
   If there is no alternative, use && when appropriate.

3. Mistake: Using if directly inside JSX braces
   Incorrect: <div>{if (ready) ...}</div>
   Correct: Use a ternary/&& expression, or decide the content before return.

4. Mistake: Missing list keys
   Prefer: items.map(item => <p key={item.id}>{item.name}</p>)
   Use stable unique identifiers, not array indexes when items can be reordered.

5. Mistake: Treating UI visibility as security
   Hiding an admin control does not protect the API. Enforce authorization on
   the backend.

6. Mistake: Overusing nested ternaries
   For complex branches, use if/else, switch, or a small helper component.

7. Mistake: Mutating state directly
   With useState, use the setter function so React can render the updated UI.

8. Mistake: Assuming a hard-coded loading flag simulates an API
   Real data fetching needs asynchronous logic and explicit loading, error,
   and success states.

============================================================
QUICK REFERENCE
============================================================

IF / ELSE:
if (condition) return <A />;
return <B />;

TERNARY:
{condition ? <A /> : <B />}

LOGICAL AND:
{condition && <A />}

FALLBACK:
{name || "Guest"}

NULLISH FALLBACK:
{value ?? defaultValue}

CONDITIONAL COMPONENT:
{showPanel && <Panel />}

RETURN NOTHING:
if (!visible) return null;

CONDITIONAL CLASS:
className={isActive ? "active" : "inactive"}

CONDITIONAL STYLE:
style={{ color: isError ? "red" : "green" }}

STATE-DRIVEN TOGGLE:
const [visible, setVisible] = useState(false);
<button onClick={() => setVisible(!visible)}>Toggle</button>
{visible && <p>Now visible</p>}
