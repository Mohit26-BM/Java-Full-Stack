React 19 + TypeScript | Beginner to Advanced

============================================================
1. WHAT ARE REACT HOOKS?
============================================================

React Hooks are special functions that let function components use React features such as state, context, refs, and lifecycle-related synchronization. Hooks let function components manage these features without writing class components.

Common Hooks:
- useState: component state.
- useEffect: synchronize with external systems.
- useContext: read a context value.
- useRef: hold a DOM reference or persistent mutable value.
- useReducer: manage state through actions and a reducer.
- useMemo: cache a calculation result.
- useCallback: cache a function reference.
- useLayoutEffect: synchronize or measure layout before browser repaint.
- useImperativeHandle: customize the handle exposed through a ref.
- useId: create IDs for accessibility relationships.
- useTransition and useDeferredValue: keep certain UI updates responsive.
- useSyncExternalStore: subscribe to a store outside React.
- useDebugValue: label custom Hook values in React DevTools.
- useInsertionEffect: specialized style insertion, mainly for library authors.
- useActionState and useOptimistic: support Action state and optimistic UI.
- use: read a supported resource such as a Promise or Context.
- Custom Hooks: reusable stateful logic written by developers.

Hooks are not ordinary utility functions. React relies on Hook call order to associate state and other data with the correct component.

============================================================
2. RULES OF HOOKS
============================================================

Rule 1: Call Hooks at the top level of a function component or custom Hook. Do not call them inside if/else blocks, loops, nested functions, event handlers, or try/catch blocks where call order may change.

Incorrect:
function Example({ enabled }: { enabled: boolean }) {
  if (enabled) {
    const [count, setCount] = useState(0); // Incorrect
  }
  return <p>Example</p>;
}

Correct:
function Example({ enabled }: { enabled: boolean }) {
  const [count, setCount] = useState(0);

  if (!enabled) return <p>Disabled</p>;

  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}

Rule 2: Call Hooks only from React function components or custom Hooks, not ordinary JavaScript functions.

Rule 3: Keep Hook calls in the same order on every render.

Rule 4: Update state immutably. Do not mutate arrays or objects already stored in state.

Rule 5: Include accurate dependencies in effect, memo, and callback dependency arrays. Use the React Hooks ESLint rules to catch mistakes.

4. useState — COMPONENT STATE
============================================================

Purpose: Store information between renders. Calling the setter requests a new render.

Syntax:
const [state, setState] = useState(initialValue);

Example 1: Counter

import { useState } from "react";

export default function Counter() {
  const [count, setCount] = useState<number>(0);

  return (
    <section>
      <h2>Counter</h2>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>Increment</button>
      <button onClick={() => setCount(count - 1)}>Decrement</button>
      <button onClick={() => setCount(0)}>Reset</button>
    </section>
  );
}

Explanation:
- useState(0) initializes count to 0.
- count is the state value for the current render.
- setCount requests a state update.
- React renders again with the new value.

Example 2: Functional updater

setCount(previousCount => previousCount + 1);

Use this form when the next value depends on the previous value.

function Counter() {
  const [count, setCount] = useState(0);

  function incrementThreeTimes() {
    setCount(current => current + 1);
    setCount(current => current + 1);
    setCount(current => current + 1);
  }

  return <button onClick={incrementThreeTimes}>Count: {count}</button>;
}

Each click increases the count by 3 because React processes the updater functions in sequence.

Example 3: Object state

type Profile = { name: string; city: string };

function ProfileEditor() {
  const [profile, setProfile] = useState<Profile>({
    name: "Praveen",
    city: "Hyderabad"
  });

  return (
    <div>
      <input
        value={profile.name}
        onChange={event =>
          setProfile(current => ({ ...current, name: event.target.value }))
        }
        aria-label="Name"
      />
      <input
        value={profile.city}
        onChange={event =>
          setProfile(current => ({ ...current, city: event.target.value }))
        }
        aria-label="City"
      />
      <p>{profile.name} lives in {profile.city}.</p>
    </div>
  );
}

The spread operator copies existing fields before replacing one. Do not mutate state directly, for example profile.name = "New Name".

Example 4: Lazy initialization

const [items, setItems] = useState(() => createInitialItems());

React calls the initializer to obtain the initial state. Use this if initialization is expensive. The initializer must be pure; development Strict Mode may call it more than once to detect impurities.

Typical uses: form values, dialog visibility, selected tabs, cart contents, todo lists, and loading/error flags.

5. useEffect — SYNCHRONIZING WITH EXTERNAL SYSTEMS
============================================================

Purpose: Synchronize a component with something outside React, such as a browser API, timer, subscription, or network connection.

Syntax:
useEffect(() => {
  // setup or synchronization
  return () => {
    // cleanup, if needed
  };
}, [dependencies]);

Dependency patterns:
useEffect(() => { ... });          // After every committed render
useEffect(() => { ... }, []);      // Initial synchronization and cleanup on unmount
useEffect(() => { ... }, [value]); // Initial synchronization and when value changes

Development Strict Mode can run an extra setup/cleanup cycle to check that cleanup is correct.

Example 1: Update document title

import { useEffect, useState } from "react";

export default function TitleCounter() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    document.title = `Count: ${count}`;
  }, [count]);

  return <button onClick={() => setCount(count + 1)}>Count: {count}</button>;
}

The effect synchronizes the browser tab title whenever count changes.

Example 2: Timer with cleanup

import { useEffect, useState } from "react";

function Clock() {
  const [seconds, setSeconds] = useState(0);

  useEffect(() => {
    const timerId = window.setInterval(() => {
      setSeconds(previous => previous + 1);
    }, 1000);

    return () => window.clearInterval(timerId);
  }, []);

  return <p>Seconds elapsed: {seconds}</p>;
}

Cleanup prevents the timer from continuing after the component is removed. The functional updater means seconds does not need to be an effect dependency.

Example 3: Fetch data with loading and error states

import { useEffect, useState } from "react";

type User = { id: number; name: string; email: string };

function Users() {
  const [users, setUsers] = useState<User[]>([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    const controller = new AbortController();

    async function loadUsers() {
      try {
        setLoading(true);
        setError(null);
        const response = await fetch(
          "https://jsonplaceholder.typicode.com/users",
          { signal: controller.signal }
        );

        if (!response.ok) throw new Error(`HTTP error: ${response.status}`);
        const data: User[] = await response.json();
        setUsers(data);
      } catch (problem) {
        if (problem instanceof Error && problem.name !== "AbortError") {
          setError(problem.message);
        }
      } finally {
        if (!controller.signal.aborted) setLoading(false);
      }
    }

    void loadUsers();
    return () => controller.abort();
  }, []);

  if (loading) return <p>Loading users...</p>;
  if (error) return <p role="alert">Error: {error}</p>;

  return (
    <ul>
      {users.map(user => (
        <li key={user.id}>{user.name} — {user.email}</li>
      ))}
    </ul>
  );
}

Important:
- fetch does not reject just because the server returns HTTP 404 or 500; check response.ok.
- AbortController cancels a request during cleanup.
- For complex applications, a data-fetching library or framework feature may provide caching, retries, and deduplication.
- Do not use an effect merely to calculate a value that can be derived during rendering.

Example 4: Window event listener

useEffect(() => {
  function handleResize() {
    console.log("Window width:", window.innerWidth);
  }

  window.addEventListener("resize", handleResize);
  return () => window.removeEventListener("resize", handleResize);
}, []);

Common mistakes: missing dependencies, forgetting cleanup, and using effects for calculations that do not need external synchronization.

6. useContext — SHARE VALUES WITHOUT PROP DRILLING
============================================================

Purpose: Make a value available to descendant components without passing it through every intermediate component as a prop.

Example: Theme context

import { createContext, useContext, useState, type ReactNode } from "react";

type Theme = "light" | "dark";

const ThemeContext = createContext<{
  theme: Theme;
  toggleTheme: () => void;
} | null>(null);

function ThemeProvider({ children }: { children: ReactNode }) {
  const [theme, setTheme] = useState<Theme>("light");

  function toggleTheme() {
    setTheme(current => current === "light" ? "dark" : "light");
  }

  return (
    <ThemeContext.Provider value={{ theme, toggleTheme }}>
      {children}
    </ThemeContext.Provider>
  );
}

function ThemePanel() {
  const context = useContext(ThemeContext);
  if (!context) throw new Error("ThemePanel must be used inside ThemeProvider");

  const { theme, toggleTheme } = context;

  return (
    <section className={theme}>
      <p>Current theme: {theme}</p>
      <button onClick={toggleTheme}>Toggle theme</button>
    </section>
  );
}

export default function App() {
  return <ThemeProvider><ThemePanel /></ThemeProvider>;
}

Explanation:
- createContext creates the context.
- The provider supplies the value.
- useContext reads the nearest matching provider.
- Consumers may re-render when the context value changes.
- Context is useful for theme, locale, and shared app information. Props are often simpler for local parent-child relationships.
- React 19 also allows <ThemeContext value={...}> as provider syntax; .Provider remains supported.

7. useRef — DOM REFERENCES AND PERSISTENT VALUES
============================================================

Purpose: useRef returns an object with a .current property. Updating .current does not itself cause a re-render.

Example 1: Focus an input

import { useRef } from "react";

function SearchBox() {
  const inputRef = useRef<HTMLInputElement>(null);

  function focusInput() {
    inputRef.current?.focus();
  }

  return (
    <div>
      <input ref={inputRef} placeholder="Search..." />
      <button onClick={focusInput}>Focus search</button>
    </div>
  );
}

React assigns the actual input element to inputRef.current after mounting. The initial null value reflects that the element does not yet exist.

Example 2: Keep a timer ID

import { useEffect, useRef, useState } from "react";

function Stopwatch() {
  const timerRef = useRef<number | null>(null);
  const [seconds, setSeconds] = useState(0);

  function start() {
    if (timerRef.current !== null) return;
    timerRef.current = window.setInterval(() => {
      setSeconds(value => value + 1);
    }, 1000);
  }

  function stop() {
    if (timerRef.current !== null) {
      window.clearInterval(timerRef.current);
      timerRef.current = null;
    }
  }

  useEffect(() => stop, []);

  return (
    <div>
      <p>{seconds} seconds</p>
      <button onClick={start}>Start</button>
      <button onClick={stop}>Stop</button>
      <button onClick={() => setSeconds(0)}>Reset</button>
    </div>
  );
}

Use state for values displayed in the UI; use refs for DOM access or mutable values that should not themselves trigger rendering. Avoid mutating refs during rendering to drive visible UI.

8. useReducer — STATE TRANSITIONS WITH ACTIONS
============================================================

Purpose: Organize complex state changes in a reducer. Useful when multiple related fields change together or many action types exist.

import { useReducer } from "react";

type State = { quantity: number };
type Action = { type: "add" } | { type: "remove" } | { type: "reset" };

function reducer(state: State, action: Action): State {
  switch (action.type) {
    case "add":
      return { quantity: state.quantity + 1 };
    case "remove":
      return { quantity: Math.max(0, state.quantity - 1) };
    case "reset":
      return { quantity: 0 };
    default:
      return state;
  }
}

export default function CartCounter() {
  const [state, dispatch] = useReducer(reducer, { quantity: 0 });

  return (
    <section>
      <h2>Cart quantity: {state.quantity}</h2>
      <button onClick={() => dispatch({ type: "add" })}>Add</button>
      <button onClick={() => dispatch({ type: "remove" })}>Remove</button>
      <button onClick={() => dispatch({ type: "reset" })}>Reset</button>
    </section>
  );
}

An action describes what happened. dispatch sends it to the reducer. The reducer calculates a new state and should be pure: no network calls, timers, or mutation of existing state.

Choose useState for straightforward state; choose useReducer for more complex transitions.

9. useMemo — CACHE A CALCULATION
============================================================

Purpose: Cache a calculation result between renders when dependencies have not changed. It is a performance optimization, not a correctness requirement.

import { useMemo, useState } from "react";

type Product = { id: number; name: string; price: number };

const products: Product[] = [
  { id: 1, name: "Keyboard", price: 1200 },
  { id: 2, name: "Monitor", price: 12000 },
  { id: 3, name: "Mouse", price: 700 },
  { id: 4, name: "Headphones", price: 2500 }
];

export default function ProductSearch() {
  const [query, setQuery] = useState("");
  const [maximumPrice, setMaximumPrice] = useState(5000);

  const filteredProducts = useMemo(() => {
    const normalizedQuery = query.trim().toLowerCase();

    return products
      .filter(product => product.name.toLowerCase().includes(normalizedQuery))
      .filter(product => product.price <= maximumPrice)
      .sort((a, b) => a.price - b.price);
  }, [query, maximumPrice]);

  return (
    <section>
      <input
        value={query}
        onChange={event => setQuery(event.target.value)}
        placeholder="Search products"
      />
      <label>
        Maximum price:
        <input
          type="number"
          value={maximumPrice}
          onChange={event => setMaximumPrice(Number(event.target.value))}
        />
      </label>
      <ul>
        {filteredProducts.map(product => (
          <li key={product.id}>{product.name}: ₹{product.price}</li>
        ))}
      </ul>
    </section>
  );
}

Dependencies must include every reactive value used by the calculation. Keep calculations pure. Do not add useMemo to every expression; measure performance first. React may discard a cached value in some circumstances, so correctness must not depend on the cache.

10. useCallback — CACHE A FUNCTION REFERENCE
============================================================

Purpose: Preserve a function reference while dependencies remain unchanged. Useful with memoized children or when a function is another Hook's dependency.

import { memo, useCallback, useState } from "react";

type ButtonProps = { onIncrement: () => void };

const IncrementButton = memo(function IncrementButton({ onIncrement }: ButtonProps) {
  console.log("IncrementButton rendered");
  return <button onClick={onIncrement}>Increment child count</button>;
});

export default function Parent() {
  const [count, setCount] = useState(0);
  const [theme, setTheme] = useState<"light" | "dark">("light");

  const increment = useCallback(() => {
    setCount(current => current + 1);
  }, []);

  return (
    <div className={theme}>
      <p>Count: {count}</p>
      <IncrementButton onIncrement={increment} />
      <button onClick={() =>
        setTheme(current => current === "light" ? "dark" : "light")
      }>
        Toggle theme
      </button>
    </div>
  );
}

memo can skip a child render when props have not changed. Without useCallback, the parent would create a new function reference on each render. The functional updater avoids adding count to the dependencies.

Difference: useMemo caches a value; useCallback caches a function reference. Neither automatically makes every app faster.

11. useLayoutEffect — MEASURE BEFORE PAINT
============================================================

Purpose: Run after React updates the DOM but before the browser repaints. Useful for layout measurement or immediate corrections that must avoid visible flicker.

import { useLayoutEffect, useRef, useState } from "react";

export default function BoxMeasurement() {
  const boxRef = useRef<HTMLDivElement>(null);
  const [height, setHeight] = useState(0);

  useLayoutEffect(() => {
    const element = boxRef.current;
    if (element) setHeight(element.getBoundingClientRect().height);
  }, []);

  return (
    <div>
      <div ref={boxRef} style={{ padding: 20, border: "1px solid black" }}>
        Measure this box
      </div>
      <p>Height: {height}px</p>
    </div>
  );
}

useLayoutEffect can block painting and affect performance. Prefer useEffect unless pre-paint work is genuinely required. Layout measurement requires a browser DOM and needs care in server-rendered applications.

12. useImperativeHandle — EXPOSE A CUSTOM REF HANDLE
============================================================

Purpose: Let a child expose selected imperative methods through a ref, rather than exposing its entire DOM node. Prefer props/state for ordinary interactions.

React 19 example:

import { useImperativeHandle, useRef, type Ref } from "react";

type TextInputHandle = { focus: () => void; clear: () => void };
type TextInputProps = { ref?: Ref<TextInputHandle> };

function TextInput({ ref }: TextInputProps) {
  const inputRef = useRef<HTMLInputElement>(null);

  useImperativeHandle(ref, () => ({
    focus() { inputRef.current?.focus(); },
    clear() { if (inputRef.current) inputRef.current.value = ""; }
  }), []);

  return <input ref={inputRef} />;
}

export default function App() {
  const fieldRef = useRef<TextInputHandle>(null);

  return (
    <div>
      <TextInput ref={fieldRef} />
      <button onClick={() => fieldRef.current?.focus()}>Focus</button>
      <button onClick={() => fieldRef.current?.clear()}>Clear</button>
    </div>
  );
}

React 19 allows ref as a prop. React 18 and earlier commonly use forwardRef to receive a ref in a function component.

13. useId — ACCESSIBLE IDS
============================================================

Purpose: Generate IDs for relationships such as label htmlFor and input id.

import { useId } from "react";

function EmailField() {
  const id = useId();

  return (
    <div>
      <label htmlFor={id}>Email address</label>
      <input id={id} type="email" />
    </div>
  );
}

Each component instance gets an ID appropriate for its React tree. Do not use useId for list keys; use stable IDs from the data. Server and client component trees must be compatible for server rendering.

14. useTransition — MARK UPDATES NON-URGENT
============================================================

Purpose: Mark state updates as non-urgent so React can prioritize urgent interactions such as typing.

import { useMemo, useState, useTransition } from "react";

const words = Array.from({ length: 5000 }, (_, index) => `Product ${index + 1}`);

export default function TransitionSearch() {
  const [input, setInput] = useState("");
  const [query, setQuery] = useState("");
  const [isPending, startTransition] = useTransition();

  const results = useMemo(
    () => words.filter(word => word.toLowerCase().includes(query.toLowerCase())),
    [query]
  );

  function handleChange(value: string) {
    setInput(value); // urgent input update
    startTransition(() => {
      setQuery(value); // non-urgent results update
    });
  }

  return (
    <section>
      <input value={input} onChange={event => handleChange(event.target.value)} />
      {isPending && <p>Updating results...</p>}
      <ul>{results.slice(0, 50).map(word => <li key={word}>{word}</li>)}</ul>
    </section>
  );
}

Do not put the controlled text input's own state update inside a transition. startTransition does not make an inefficient algorithm intrinsically faster; consider list virtualization for very large lists.

15. useDeferredValue — DEFER A VALUE
============================================================

Purpose: Allow part of the UI to use a delayed version of a rapidly changing value, helping keep urgent interactions responsive.

import { memo, useDeferredValue, useMemo, useState } from "react";

const products = Array.from({ length: 4000 }, (_, index) => `Product ${index + 1}`);

const Results = memo(function Results({ query }: { query: string }) {
  const results = useMemo(
    () => products.filter(item => item.toLowerCase().includes(query.toLowerCase())),
    [query]
  );

  return <ul>{results.slice(0, 40).map(item => <li key={item}>{item}</li>)}</ul>;
});

export default function DeferredSearch() {
  const [query, setQuery] = useState("");
  const deferredQuery = useDeferredValue(query);

  return (
    <div>
      <input value={query} onChange={event => setQuery(event.target.value)} />
      <Results query={deferredQuery} />
    </div>
  );
}

Difference:
- useTransition marks a particular state update as non-urgent.
- useDeferredValue lets a consumer use a delayed version of a value.
Neither replaces improving inefficient code.

16. useSyncExternalStore — SUBSCRIBE TO AN EXTERNAL STORE
============================================================

Purpose: Read a value from a store outside React and subscribe to its changes.

Example: Browser online status

import { useSyncExternalStore } from "react";

function subscribe(callback: () => void) {
  window.addEventListener("online", callback);
  window.addEventListener("offline", callback);

  return () => {
    window.removeEventListener("online", callback);
    window.removeEventListener("offline", callback);
  };
}

function getSnapshot() {
  return navigator.onLine;
}

function getServerSnapshot() {
  return true; // Example fallback; choose a value appropriate to the app.
}

export default function OnlineStatus() {
  const isOnline = useSyncExternalStore(subscribe, getSnapshot, getServerSnapshot);
  return <p>{isOnline ? "You are online" : "You are offline"}</p>;
}

getSnapshot should return a stable snapshot until the store changes. subscribe must return an unsubscribe function. getServerSnapshot is needed for server-rendering support. This Hook is often useful for library authors and external store integrations.

17. useDebugValue — LABEL A CUSTOM HOOK IN DEVTOOLS
============================================================

Purpose: Add a label for a custom Hook in React DevTools. This does not affect the rendered UI.

import { useDebugValue, useState } from "react";

function useDemoStatus() {
  const [online, setOnline] = useState(true);
  useDebugValue(online ? "Online" : "Offline");
  return { online, setOnline };
}

export default function App() {
  const { online, setOnline } = useDemoStatus();

  return (
    <button onClick={() => setOnline(value => !value)}>
      Status: {online ? "Online" : "Offline"}
    </button>
  );
}

This demonstrates labeling only; a real online-status Hook should connect to an actual source. useDebugValue is mainly helpful when building reusable Hooks.

18. useInsertionEffect — SPECIALIZED STYLE INSERTION
============================================================

Purpose: Intended primarily for CSS-in-JS library authors that must insert styles before layout effects run. Most application developers should not need it.

import { useInsertionEffect } from "react";

function StyledContent() {
  useInsertionEffect(() => {
    // A CSS-in-JS library might insert a style rule here.

}

Use a CSS-in-JS library's recommended integration rather than creating a custom style injection mechanism. This is not a general-purpose effect.

19. useActionState — MANAGE AN ACTION'S RESULT
============================================================

Purpose: Manage the result of an Action and connect it to a form. Available in modern React, including React 19.

import { useActionState } from "react";

type FormState = { message: string };

async function signupAction(
  previousState: FormState,
  formData: FormData
): Promise<FormState> {
  const email = String(formData.get("email") ?? "").trim();

  if (!email.includes("@")) {
    return { message: "Enter a valid email address." };
  }

  // Demo only: replace with a real server request.
  await new Promise(resolve => setTimeout(resolve, 500));
  return { message: `Submitted signup for ${email}.` };
}

export default function SignupForm() {
  const [state, formAction, isPending] = useActionState(
    signupAction,
    { message: "" }
  );

  return (
    <form action={formAction}>
      <label>
        Email:
        <input name="email" type="email" required />
      </label>
      <button disabled={isPending}>
        {isPending ? "Submitting..." : "Sign up"}
      </button>
      <p aria-live="polite">{state.message}</p>
    </form>
  );
}

The Action receives previous state and FormData. The Hook returns the latest state, a dispatcher, and a pending flag. A real application must validate data on the server and handle errors securely.

20. useOptimistic — SHOW OPTIMISTIC UI
============================================================

Purpose: Temporarily show an expected result while an Action is in progress. This can make the UI feel faster, but it does not prove the server operation succeeded.

import { useOptimistic, useState, useTransition } from "react";

type Message = { id: number; text: string };

export default function ChatDemo() {
  const [messages, setMessages] = useState<Message[]>([
    { id: 1, text: "Welcome!" }
  ]);

  const [optimisticMessages, addOptimisticMessage] = useOptimistic(
    messages,
    (current, newText: string) => [
      ...current,
      { id: Date.now(), text: newText }
    ]
  );

  const [, startTransition] = useTransition();

  function sendMessage(formData: FormData) {
    const text = String(formData.get("message") ?? "").trim();
    if (!text) return;

    startTransition(async () => {
      addOptimisticMessage(text);

      // Demo delay: replace with an actual API call.
      await new Promise(resolve => setTimeout(resolve, 700));

      setMessages(current => [...current, { id: Date.now(), text }]);
    });
  }

  return (
    <div>
      <form action={sendMessage}>
        <input name="message" required placeholder="Type a message" />
        <button>Send</button>
      </form>
      <ul>
        {optimisticMessages.map(message => (
          <li key={message.id}>{message.text}</li>
        ))}
      </ul>
    </div>
  );
}

In production, handle server failures and reconcile the server response. Use robust IDs rather than relying on Date.now if duplicate IDs are possible.

21. use — READ A PROMISE OR CONTEXT
============================================================

Purpose: The React use API can read a supported resource such as a Promise or Context. Unlike most Hooks, use may be called inside conditions and loops, subject to its own rules. It is not a replacement for every Hook.

import { Suspense, use } from "react";

type User = { name: string; email: string };

function UserDetails({ userPromise }: { userPromise: Promise<User> }) {
  const user = use(userPromise);
  return (
    <section>
      <h2>{user.name}</h2>
      <p>{user.email}</p>
    </section>
  );
}

const userPromise: Promise<User> = Promise.resolve({
  name: "Asha",
  email: "asha@example.com"
});

export default function App() {
  return (
    <Suspense fallback={<p>Loading user...</p>}>
      <UserDetails userPromise={userPromise} />
    </Suspense>
  );
}

A Promise read with use can suspend rendering until it resolves. Suspense supplies the loading fallback. Reuse a stable Promise rather than creating a new one on every render. Handle rejected Promises through an Error Boundary or the application's error strategy. Exact support depends on React version and framework/runtime setup.

22. CUSTOM HOOKS — REUSE STATEFUL LOGIC
============================================================

A custom Hook is a function whose name starts with "use" and that may call other Hooks. Custom Hooks share logic, not a shared state instance by default.

Example 1: useCounter

import { useState } from "react";

function useCounter(initialValue = 0) {
  const [count, setCount] = useState(initialValue);

  function increment() {
    setCount(value => value + 1);
  }

  function decrement() {
    setCount(value => value - 1);
  }

  function reset() {
    setCount(initialValue);
  }

  return { count, increment, decrement, reset };
}

export default function App() {
  const firstCounter = useCounter(0);
  const secondCounter = useCounter(10);

  return (
    <div>
      <h2>First: {firstCounter.count}</h2>
      <button onClick={firstCounter.increment}>First +</button>
      <h2>Second: {secondCounter.count}</h2>
      <button onClick={secondCounter.increment}>Second +</button>
      <button onClick={secondCounter.reset}>Reset second</button>
    </div>
  );
}

Example 2: useLocalStorage (simple browser-focused example)

import { useEffect, useState } from "react";

function useLocalStorage(key: string, initialValue: string) {
  const [value, setValue] = useState(() => {
    if (typeof window === "undefined") return initialValue;

    try {
      return window.localStorage.getItem(key) ?? initialValue;
    } catch {
      return initialValue;
    }
  });

  useEffect(() => {
    try {
      window.localStorage.setItem(key, value);
    } catch {
      // Storage may be blocked or unavailable.
    }
  }, [key, value]);

  return [value, setValue] as const;
}

export default function NamePreference() {
  const [name, setName] = useLocalStorage("preferred-name", "");

  return (
    <label>
      Preferred name:
      <input value={name} onChange={event => setName(event.target.value)} />
    </label>
  );
}

This is intentionally simple. Server-rendered applications need to consider hydration consistency. If key changes after mounting, a production-quality Hook should define how to load the new key. Do not store sensitive information in localStorage without a deliberate security assessment.

23. COMMONLY CONFUSED CONCEPTS
============================================================

State versus ref
- State updates trigger rendering.
- Ref updates do not trigger rendering.
- Use state for information shown in the UI.
- Use refs for DOM access or mutable values that do not drive the UI.

useEffect versus useLayoutEffect
- useEffect is the normal choice for external synchronization.
- useLayoutEffect runs before repaint and may block painting.
- Prefer useEffect unless pre-paint work is needed.

useMemo versus useCallback
- useMemo caches a calculation result.
- useCallback caches a function reference.
- Both are optimizations, not requirements for correctness.

useState versus useReducer
- useState is ideal for simple state.
- useReducer organizes more complex transitions.

useTransition versus useDeferredValue
- useTransition marks a state update as non-urgent.
- useDeferredValue lets a consumer use a delayed version of a value.

Context versus props
- Props explicitly pass data from parent to child.
- Context shares a value across descendant levels.
- Context changes can cause consumers to re-render.

Built-in Hook versus custom Hook
- Built-in Hooks come from React.
- Custom Hooks are developer-written functions that reuse stateful logic.

26. BEST PRACTICES CHECKLIST
============================================================

- Call Hooks at the top level of function components or custom Hooks.
- Keep Hook calls in the same order on every render.
- Use state for values that affect rendered output.
- Update arrays and objects immutably.
- Use functional state updaters when the next value depends on the previous value.
- Use effects for external synchronization, not every calculation.
- Clean up timers, listeners, and subscriptions.
- Declare accurate dependencies for effects, callbacks, and memoized calculations.
- Prefer useEffect over useLayoutEffect unless pre-paint work is necessary.
- Apply useMemo and useCallback only when they provide a useful optimization.
- Keep reducers pure.
- Use stable data IDs for list keys; do not use useId as a list key.
- Treat optimistic UI as temporary until the real operation succeeds.
- Validate data on the server and protect sensitive information.
- Test in development Strict Mode; extra checks can reveal cleanup and purity bugs.
- Consult official React documentation when behavior depends on version or framework.
